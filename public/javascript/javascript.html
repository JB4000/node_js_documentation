JavaScript

This page will contain some useful approaches to guidelines from the course on using JavaScript with Node.JS and in general. The page will present code examples from the course with short explanations to support the guidelines. Subjects covered will be variables, scope, data types, type coercion, strings and template literals.

Declaring variables with const, let and var

Rule for the course: use const for declaring variables as default, change to letif reassignment is necessary. Never use var.

The reason for this guideline is to prevent unintentional reassignments or mutations. Here are some illustrations of the problems that can arise. 


                const someNumber = 255;
                
                let someNumber = 255;

When using const in the declaration the variable is constant in assignment, so the value of someNumber can not change. When using let reassignment is possible, so the value can change. For example using someNumber++ An example of a case for let would be a counter that has to increment. If the variable contains a value that is a reference, then that reference can not change. But the data the refernce points to can change. That means that the properties of an object can change without reassignment of the variable. Properties can be added too. 


                    const person = {
                        name: "Paul"
                    };

                    person.name = "Heather";
                    person.age = 32;

The above example is an object, but the same is true for arrays. 


                    const roles = ["Teacher"];

                    roles.push("Student");

In both cases no reassignment have taken place. const provides more safety with primitive values then reference types, but but there is still protection against reassignment of the reference. 


                const roles = ["Teacher"];

                roles = ["Student"];

The example above attempts to reassign the reference to a whole new array. const prevents that.

Scope and var

var allows reassignment on a larger scope than let. That situation can be even more comple to manage. let has block scope where var has function scope. 


                    {
                        var someValue = 123;
                        {
                            var someValue = 456;
                        }
                        console.log(someValue); // 456
                    }

                    {
                        let someOtherValue = true;
                        {
                            let someOtherValue = false;
                        }
                        console.log(someOtherValue); // true
                    }

In the last example the variable someOtherValue will hold the value false in the inner block and the value true in the outer block. Because of the scope these are two different variables. The inner variable temporarily shadows the outer variable. In the first example the inner statement will instead reassign the value 456 to the existing variable because the function scope goes beyond the block. 


                    for (let i = 0; i <= 5; i++) {
                        setTimeout(() => {
                            console.log(i);
                        }, 1000);
                    }
                    // 0,1,2,3,4,5

                    for (var i = 0; i <= 5; i++) {
                        setTimeout(() => {
                            console.log(i);
                        }, 1000);
                    }
                    // 6,6,6,6,6,6

The above example is an illustration of how code is more predictable using when using let for reassignment instead of using var. The first example prints the sequence as predicted because the value send to the callback function does not change. There will be 6 different callback functions called and they all have different values for i. In the last example the i variable in every callback function will be reassigned evry time the update part of the loop makes an increment of i. The value will be 6 because of the last increment made before the comparison that results in the loop not continuing.

Type coercion

JavaScript can automatically coerce values from one type to another. It can be used in clever ways, but we will avoid on the course to make our code more predictable.

Rule for the course: Always use strict equality checks, never use loose equality checks 


                    5 == "5"

                    5 === "5"

In the example a number is being compared to a string. The first line uses loose equality that coerces the string to a number before making the comparison. Therefore the expression will be true. The last example uses strict equality which never coerces one type into another type but simple considers different types as unequal. Therefore the expression will be false. The same principle applies to loose inequality and strict inequality 


                    5 != "5"   // false
                    5 !== "5"  // true

When we have to compare across types we explicitly use conversion methods instead of coercion. These methods are named from the type they convert. Here are a few examples. 


                    Number("5");
                    String(5);
                    Boolean("true");

String concatenation is another issue where we want to avoid coercion. 


                    console.log("150" + 100); 
                    // 150100

In the above example the number 100 is coerced to string causing string concatenation instead of addition. The result can be made into addition if we explicitly convert the string to a number. 


                    console.log(Number("150") + 100);
                    // 250

String concatenation can also happen with console.log()in cases where we simply want separate values.

Rule for the course: Always use comma in console.log() to separate values 


                    const a = 10;
                    const b = 20;

                    console.log("Values:", a, b);     //Values: 10 20
                    console.log("Values: " + a + b);  //Values:1020

Data types

Primitive types

JavaScript has a range of types where some are primitive types and some are reference types. Here is a list of primitive types 


                        const a = "Hello";      //string
                        const b = true;         //boolean
                        const c = 42;           //number
                        const d = 42n;          //bigint

                        const e = undefined;    //undefined
                        const f = null;         //null
                        const g = Symbol("id"); //symbol

string is for text and boolean is for boolean values. number can hold positive and negative floats. bigint is for holding precise values of very big integers that goes beyond the range of number. symbol is not used in this course. It is holding values returned from Symbol() when wanting to use unique values for id in certain context. undefined represents the absence of a value. A function will also return undefined if there is no return statement or if the return statement is not combined with a value is in return; null on the other hand is used to show that a variable is intentionally without a value. 


                        console.log(typeof "Hello"); //string

typeof will return the type of a value og variable. However, using typeof with null will return object, even though null is a primitive type.

Reference types


                        const g = { name: "Johnny", age: 25 };
                        const h = ["cat", "dog", "bird"];

When using typeof on these two examples th result will be object, because object and array hold references to data in memory. The properties of the object and the items in the array can be changed, but the reference can not be changed when const is used. Objects are mutable even when using const

Strings and template literals

There are multiple ways of printing strings that can have different results 


                    const age = 25;

                    console.log("John said: 'Hi' to the dog");
                    console.log('John said: "Hi" to the dog');
                    console.log(`John is ${age} years old. He uses "Instagram" and 'TikTok'`);

Single quotes can be nested inside double quotes, and the other way around. Whatever quote type starts the string will also end it. Everything before that is considered part of the string and anything after is not. It is not possible to use the same type of quotes nested, that will simply cut the string as soon as the second quote is introduced. Unless you escape it with \' Template literals using backticks can use variables and expressions inside braces and new lines. Interpolation refers to the evaluation of the expression before making it part of th string. Single and double quotes is just considered part of the string. These are all valid, but messy, statements that will print in their entirity.

                    const greeting = 'It\'s me, Johnny';
                    const greetingTwo = "Hey, my old '''''friend'";

Functions and callbacks

Functions can be defined in different ways in JavaScript. A function declaration defines the function directly with a name. 


        function playingGuitarAction(name) {
            return `${name} likes to play guitar`;
        }

Function declarations are hoisted. That means that the function can be called by code that appears before the function declaration in the file. 


        sayHello();

        function sayHello() {
            console.log("Hello");
        }

A function can also be created as a function expression and assigned to a variable. In this example the function itself is anonymous because it does not have a name in the function definition. 


        const playingGuitarAction = function (name) {
            return `${name} likes to play guitar`;
        };

An arrow function is another syntax for creating a function. 


        const watchingMoviesAction = (name) => {
            return `${name} likes to watch movies`;
        };

If an arrow function only contains a single expression, the braces and the return keyword can be left out. The value of the expression will then be returned automatically. 


        const watchingMoviesAction = (name) => `${name} likes to watch movies`;

Functions as values and callbacks

Functions are first-class citizens in JavaScript. This means that functions can be treated like other values. They can for example be assigned to variables and passed as arguments to other functions. 


            function genericActionPerformer(name, action) {
                return action(name);
            }

            function playingGuitarAction(name) {
                return `${name} likes to play guitar`;
            }

            genericActionPerformer("Elias", playingGuitarAction);

The second argument in the call to genericActionPerformer() is a reference to the function playingGuitarAction. There are no parentheses after the function name, so the function is not called at this point. The reference is assigned to the parameter action.

Inside genericActionPerformer() the statement action(name) calls the function that was passed as an argument. In this example name contains the value "Elias", so playingGuitarAction() is called with that value.

A function passed to another function like this is a callback function. The function receiving the callback can decide when to call it.

Adding parentheses when passing the function would make an important difference. 


            genericActionPerformer("Elias", playingGuitarAction());

Here playingGuitarAction() is called first and its returned value is passed to genericActionPerformer(). The returned value is a string and not a function reference. When genericActionPerformer() later tries to call action(name), it would therefore be trying to call a string as a function.

Random numbers

Math.random() returns a number from 0 inclusive to 1 exclusive. That means that 0 is a possible value, but 1 is not. 


        Math.random();
        // 0 <= result < 1

To generate random integers in a specific range we can scale this value and use Math.floor(). Math.floor() rounds down to the nearest integer. It does not exclude 0. If the value is 0, Math.floor(0) is also 0.

This function returns a random integer where both min and max are included: 


        function getRandomInt(min, max) {
            return Math.floor(Math.random() * (max - min + 1) + min);
        }

max - min + 1 gives the number of possible integer values in the range. The extra 1 is needed because both ends of the range are included. Adding min moves the lowest possible result from 0 to the value given as min.

Date and time

JavaScript has a Date object for working with dates and time. Calling new Date() creates a new Date object containing the current date and time. 


            const currentDate = new Date();

The variable contains a reference to the Date object. The new keyword creates a new instance using Date as a constructor.

Getting values from a Date

A Date object has methods for getting the different parts of the date and time. 


            const currentDate = new Date();

            currentDate.getFullYear();
            currentDate.getMonth();
            currentDate.getDate();
            currentDate.getDay();

            currentDate.getHours();
            currentDate.getMinutes();
            currentDate.getSeconds();

getFullYear() returns the year. getMonth() returns the month as a zero-indexed value from 0 to 11. January is therefore 0 and December is 11.

getDate() returns the day of the month from 1 to 31. This should not be confused with getDay(), which returns the weekday as a zero-indexed value from 0 to 6, starting with Sunday.

The time methods return hours from 0 to 23 and minutes and seconds from 0 to 59.

Zero-indexed months

Because getMonth() returns a zero-indexed month, the value can be used directly as an index in an array where January is the first element. 


            const months = [
                'January',
                'February',
                'March',
                'April',
                'May',
                'June',
                'July',
                'August',
                'September',
                'October',
                'November',
                'December'
            ];

            const currentDate = new Date();

            console.log(months[currentDate.getMonth()]);

The numeric Date constructor also uses zero-indexed months. 


            const date = new Date(2026, 8, 29);
            // September 29, 2026

Timestamps and durations

Date.now() returns a number containing the number of milliseconds since January 1, 1970 UTC. This point in time is called the Unix epoch. 


            const timestamp = Date.now();

            console.log(typeof timestamp);
            // number

Dates can also be subtracted from each other. The result is a number containing the duration between the dates in milliseconds. 


            const timelineStart = new Date('1950-01-01');
            const timelineEnd = new Date('2100-01-01');

            const totalTimeline = timelineEnd - timelineStart;

This makes it possible to use dates in calculations. For example, the position of a date on a timeline can be calculated from its distance from the beginning compared with the complete duration. 


            const distance = date - timelineStart;
            const position = (distance / totalTimeline) * 100;

Formatting dates

We can create our own arrays of month and weekday names, but JavaScript can also format dates according to a locale with toLocaleDateString(). 


            const currentDate = new Date();

            const month = currentDate.toLocaleDateString(
                'en-GB',
                { month: 'long' }
            );

            const weekday = currentDate.toLocaleDateString(
                'en-GB',
                { weekday: 'long' }
            );

The locale controls how the date is formatted. Using 'long' for the month or weekday asks for the complete written name instead of an abbreviated or numeric version.

Using an array together with getMonth() is a simple way of translating the zero-indexed month ourselves. toLocaleDateString() is a more developed solution when the date should be formatted for a particular locale.

UTC and local time

UTC is a common time standard that does not depend on a particular local time zone. The same moment can have a different displayed clock time depending on the local time zone. 


            2026-09-18T08:03:15.983Z

The Z at the end of an ISO timestamp indicates UTC and is also called Zulu time.

Loops and loop methods

Rule for the course: prefer loop methods when working with arrays. Traditional loops can still be useful when the problem is naturally based on counting.

for...of and for...in

for...of can be used to iterate through the values of an array. 


            const numbers = [4, 5, 6];

            for (const number of numbers) {
                console.log(number);
            }

            // 4
            // 5
            // 6

for...in instead iterates through property keys. Arrays are also objects in JavaScript, so when it is used on an array the keys will normally be the indexes rather than the values. For arrays we will normally use for...of or an array loop method instead.

forEach

forEach() calls a callback function once for each element in an array. It is useful when we want something to happen for each element without creating a new result array. 


            const numbers = [1, 2, 3, 4, 5];

            numbers.forEach((number) => {
                console.log(number * 2);
            });

The callback can receive the current value, the index and the complete array. forEach() itself returns undefined.

map

map() is used when we want to transform every element and keep the resulting values. The return value from each callback call is collected into a new array. 


            const numbers = [1, 2, 3, 4, 5];

            const doubledNumbers = numbers.map((number) => number * 2);

            // doubledNumbers: [2, 4, 6, 8, 10]
            // numbers:        [1, 2, 3, 4, 5]

There is a one-to-one relationship between the original array and the returned array. One value is returned by the callback for every element in the original array.

filter

filter() is used to create a new array containing only the elements that pass a condition. The callback returns a boolean value that filter() uses to decide if the element should be included. 


            const countriesWithGDPBelowThousand = countries.filter(
                (country) => country.gdp < 1000
            );

Unlike map(), the returned array can contain fewer elements than the original array because some elements can be filtered out.

find and findIndex

find() returns the first element that matches a condition. If no element matches, it returns undefined. 


            const foundAnimal = animals.find((animal) => animal.id === id);

findIndex() works with a condition in the same way, but returns the index of the matching element instead. If there is no match it returns -1. 


            const foundAnimalIndex = animals.findIndex(
                (animal) => animal.id === id
            );

The index is useful when we need to change or remove an element at a specific position in an array.

reduce

reduce() can reduce the values of an array into one result. An example could be calculating the sum of all numbers in an array. 


            const numbers = [1, 2, 3, 4, 5];

            const sum = numbers.reduce(
                (accumulator, value) => accumulator + value,
                0
            );

            // 15

The last argument, 0, is the initial value of the accumulator. For every element the callback receives the current accumulator and the current value. The returned result becomes the accumulator used for the next element.

Side effects and references

Creating a new array with a loop method does not automatically mean that the objects inside it are copies. Objects are reference types, so two arrays can contain references to the same object. 


            const countriesWithGDPBelowThousand = countries.filter(
                (country) => country.gdp < 1000
            );

            countriesWithGDPBelowThousand[0].gdp = 2000;

If the object in both arrays is the same object, changing its gdp property through one reference will also be visible through the other reference. The property of the existing object has been mutated.

When we want to transform objects without changing the existing objects, we can instead create new objects. 


            const countriesWithGDPUpdated = countries.map((country) => {
                return {
                    ...country,
                    gdp: country.gdp * 2
                };
            });

The spread syntax copies the properties from country into a new object. The gdp property comes afterwards and therefore replaces the copied value with the new value. The original object is not mutated.
