Express & HTTP

Express is a framework for Node.js that we use to create a web server and handle HTTP requests. A client can send a request to the server, the server can run code based on the request, and then send a response back to the client.

In this course the client will be a browser or another program making HTTP requests, while our Node.js application running Express is the server.

Creating an Express server

Express first has to be imported into the project. We can then create an Express application and tell it which port to listen on. 


            const express = require("express");  // Our initial CommonJS approach
            const app = express();

            app.listen(8080);

express() creates the server by creating an instance of Express. app.listen(8080) makes the server listen for requests on port 8080.

Routes and callbacks

We define routes to decide what the server should do when it receives different HTTP requests. 


            app.get("/animals", (req, res) => {
                res.send({ data: animals });
            });

app.get() takes two arguments in this example. The first is the endpoint path "/animals". The second is a callback function. Express can call the callback when a GET request matching that path is received.

req and res are parameters of the callback function. They are not arguments that we supply when defining the route. Express calls the function and provides the request and response objects.

The request object req contains information about the request from the client. The response object res is used when sending the response back to the client. 


            res.send({ data: animals });

In this example res.send() sends an object as the HTTP response.

Anatomy of a URL

Different parts of a URL have different purposes. For example: 


            http://localhost:8080/animals/7?includeHabitat=true

This URL can be divided into these parts:

  • http - protocol
  • localhost - hostname
  • 8080 - port
  • /animals/7 - endpoint path
  • ?includeHabitat=true - query string

The path and query string can both be used to send information to the server, but they are used in different ways.

Path parameters

A route can contain a variable part of the path. In Express we define this using a colon. 


            app.get("/animals/:id", (req, res) => {
                console.log(req.params.id);
            });

If the client requests /animals/7, the value "7" is available as req.params.id. Values received from the URL are strings, so we can explicitly convert the value when we need a number. 


            const id = Number(req.params.id);

The name id comes from :id in the route definition. A route can also contain more than one path parameter. 


            app.get("/beers/:beerType/:amount", (req, res) => {
                res.send({
                    data: `You ordered ${req.params.amount} of ${req.params.beerType}`
                });
            });

Query parameters

Query parameters are written after ? in the URL. More than one query parameter can be separated with &. 


            /animals?habitat=water&limit=10

Express makes the query parameters available through req.query. 


            app.get("/animals", (req, res) => {
                console.log(req.query.habitat);
                console.log(req.query.limit);
            });

Path parameters are useful when a value identifies a particular resource. Query parameters can be used for additional options about the request, for example filtering.

Sending data in the request body

Not all data is in the URL. A client can also send data in the body of an HTTP request. For example when creating an animal. 


            {
                "name": "Otter",
                "age": 4
            }

If the body, like in this case, contains JSON, Express needs middleware that parses the JSON before we can work with it as a JavaScript object. 


            app.use(express.json());

express.json() is middleware. It parses JSON from the request body and makes the resulting JavaScript data available through req.body. 


            app.post("/animals", (req, res) => {
                console.log(req.body.name);
                console.log(req.body.age);
            });

In this example req.body.name and req.body.age access properties from the JavaScript object created by parsing the JSON body.

Where request data is found

The location of data in the request determines where we read it in Express. The placement depends on the type of request. 


            req.params
            req.query
            req.body
  • req.params contains values from path parameters.
  • req.query contains values from the query string.
  • req.body contains parsed data from the request body.

For example, a GET request will often carry information in the path or query string, while a POST request will often carry data in the body.

Redirects

A redirect sends the user from one URL to another. We can navigate to another page in the browser, or the server can tell the browser to make a new request to a different URL.

Navigation in the browser

One way to navigate to another page is by using a link in HTML. 


            <a href="/">Go to frontpage</a>

When the user clicks the link, the browser navigates to the URL in the href attribute.

We can also navigate using JavaScript. 


            window.location.href = '/'';
            location.href = '/';

This changes the current URL and navigates to the frontpage. The previous page normally remains in the browser history, so it is possible to go back in the browser.

Another option is location.replace(). 


            window.location.replace('/'');
            location.replace('/');

This replaces the current history entry, so the user normally cannot return to that entry using the browser's back button.

Meta refresh and delayed navigation

There are other ways to navigate to another page from the browser. We can use a meta refresh tag in HTML or JavaScript with a delay.

Meta refresh

A meta refresh tag can tell the browser to navigate to another URL after a specified number of seconds. The tag is placed inside the HTML head. 


            <head>
                <meta http-equiv="refresh" content="3;url=/">
            </head>

In this example, the browser waits three seconds before navigating to the frontpage.

The value before the semicolon is the delay in seconds, and the URL is the destination.

Meta refresh works without JavaScript, but we will typically use a normal link for navigation or an HTTP redirect when a page has moved.

Delayed navigation with setTimeout

We can use setTimeout() in JavaScript when we want to run code after a delay. 


            setTimeout(() => {
                location.href = "/";
            }, 3000);

setTimeout() takes a callback function and a delay in milliseconds.

In this example, the callback runs after 3000 milliseconds, which is three seconds. The callback then navigates to the frontpage.

This delay could be used to show a message before navigating to another page.

Both examples make the browser navigate to another URL. They are different from res.redirect(), where Express sends an HTTP redirect response to the client.

Redirecting from Express

A server-side redirect happens when the server responds to a request by telling the client to request another URL.

In Express we can use res.redirect(). 


            app.get("/old-page", (req, res) => {
                res.redirect("/new-page");
            });

When a client requests /old-page, Express responds with a redirect to /new-page.

The browser can then make a new request to the new URL.

HTTP redirect status codes

A server-side redirect uses an HTTP response status code and a Location header to tell the client where to go.

By default, res.redirect() uses status code 302, which is a temporary redirect. 


            res.redirect("/new-page");

We can also specify the status code ourselves. For example, 301 means that a resource has moved permanently. 


            res.redirect(301, "/new-page");

A redirect response includes a Location header with the destination URL. 


            HTTP/1.1 302 Found
            Location: /new-page

The important difference is that the server does not send the content of the new page directly in this response. It tells the client where to make another request.
