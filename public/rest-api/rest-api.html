REST APIs

A REST API gives a structured way of working with resources on a server using HTTP. In the first REST API in the course we keep the data in an array instead of using a database. We focus on the routes and the HTTP requests before possibly adding persistence later.

REST conventions

We use conventions when designing REST endpoints. The HTTP method should describe the action and the endpoint should describe the resource.

Rule for the course: use nouns in plural for collections. For a collection of animals we therefore use /animals instead of something like /getAnimals. 


            GET /animals
            GET /animals/:id
            POST /animals
            PUT /animals/:id
            PATCH /animals/:id
            DELETE /animals/:id

The HTTP method shows what kind of operation is requested, so we do not need to put the operation into the endpoint name.

The order of the endpoint should also follow the structure of the resources. A specific animal belongs to the animals collection, so its id comes after /animals. 


            /animals/:id

CRUD and HTTP methods

CRUD stands for Create, Read, Update and Delete. These operations can be connected to HTTP methods when designing a REST API.

  • POST - Create
  • GET - Read
  • PATCH or PUT - Update
  • DELETE - Delete

The same resource path can therefore be used with different HTTP methods. The combination of the HTTP method and endpoint tells the server which operation is requested.

Reading resources

Getting the collection

A GET request to /animals can return the complete collection. 


                app.get("/animals", (req, res) => {
                    res.send({ data: animals });
                });

Getting one resource

When we want one specific animal, the id can be part of the endpoint path. The path parameter from the URL is a string, while the ids in our animal objects are numbers. We therefore convert the provided id before comparing it with strict equality. 


                app.get("/animals/:id", (req, res) => {
                    const providedId = Number(req.params.id);

                    const foundAnimal = animals.find(
                        (animal) => animal.id === providedId
                    );

                    if (!foundAnimal) {
                        return res.status(404).send({
                            errorMessage: `No animal found by id ${providedId}`
                        });
                    }

                    res.send({ data: foundAnimal });
                });

find() returns the first element that matches the condition. If no animal matches, it returns undefined.

In that situation the server sends status code 404, meaning Not Found.

One request should get one response

After sending the 404 response we use return. 


            if (!foundAnimal) {
                return res.status(404).send({
                    errorMessage: `No animal found by id ${providedId}`
                });
            }

res.status(404).send() sends the response. return is used to stop execution of the route callback afterwards. Without stopping the function, later code could continue and try to send another response for the same request.

Rule for the course: one request should have one response.

Creating a resource

A POST request can be used to create a new animal. At this stage of the course we do not have a database, so an incrementing variable is used to imitate an automatically generated id in a relational database. 


            let nextId = 3;

If the existing animals have ids 1 and 2, the next created animal can get id 3. The variable is then incremented so it is ready for the next animal. 


            app.post("/animals", (req, res) => {
                const providedAnimal = req.body;

                providedAnimal.id = nextId++;

                animals.push(providedAnimal);

                res.send({ data: providedAnimal });
            });

The JSON body has already been parsed by express.json(), so the provided animal can be accessed through req.body.

The server decides the id. We do not want a client to decide which id a new resource should have.

Updating a resource with PATCH

PATCH is used when we want to update only some properties of an existing resource. Properties that were not supplied should still be kept.

First we find the index of the animal we want to update. 


            const foundAnimalIndex = animals.findIndex(
                (animal) => animal.id === providedId
            );

findIndex() returns the index of the first matching element. If nothing matches, it returns -1. In that case we respond with 404. 


            if (foundAnimalIndex === -1) {
                return res.status(404).send({
                    errorMessage: `No animal found by id ${providedId}`
                });
            }

If an index was found we can then create a new object containing the existing values and the supplied changes. 


            const animalToCreate = {
                ...foundAnimal,
                ...providedAnimal,
                id: providedId
            };

The spread operator spreads the properties from an object into the new object. Properties can occur more than once while the object is being created. If that happens, the last value is the one that is kept.

That is why the order is important. The existing animal is added first. The properties supplied by the client come afterwards and can override the old values. Finally id: providedId overrides any id that might have been in the request body. We should only use ids from path variables. 


            app.patch("/animals/:id", (req, res) => {
                const providedId = Number(req.params.id);

                const foundAnimalIndex = animals.findIndex(
                    (animal) => animal.id === providedId
                );

                if (foundAnimalIndex === -1) {
                    return res.status(404).send({
                        errorMessage: `No animal found by id ${providedId}`
                    });
                }

                const providedAnimal = req.body;
                const foundAnimal = animals[foundAnimalIndex];

                const animalToCreate = {
                    ...foundAnimal,
                    ...providedAnimal,
                    id: providedId
                };

                animals[foundAnimalIndex] = animalToCreate;

                res.send({ data: animalToCreate });
            });

The animals variable does not have to be reassigned. The array itself is mutated by changing which object reference is stored at the found index.

PUT and PATCH

PATCH and PUT are both connected to updating resources, but we have discussed an important distinction between them in class.

PATCH is a partial update. We send the properties that should change and preserve the other properties of the existing resource.

The strict PUT approach explained in class treats PUT as replacement. The old database row is deleted, including its id, and a new row is created from the supplied data with a new id.

We also discussed that PUT is often not implemented that strictly in practice. It is common to see it used to update all the values of an existing resource while keeping its id. This makes the practical implementation look closer to an update than the strict replacement approach discussed in class.

Deleting a resource

DELETE is used to remove a resource. Again we first find the index of the animal with the requested id. 


            app.delete("/animals/:id", (req, res) => {
                const providedId = Number(req.params.id);

                const foundAnimalIndex = animals.findIndex(
                    (animal) => animal.id === providedId
                );

                if (foundAnimalIndex === -1) {
                    return res.status(404).send({
                        errorMessage: `No animal found by id ${providedId}`
                    });
                }

                animals.splice(foundAnimalIndex, 1);

                res.status(204).send();
            });

splice() mutates the array. The first argument is the index where the operation starts and the second argument is the number of elements to remove. In this case one animal is removed.

The response uses status code 204. The resource was successfully deleted and there is no response body to send back. We could choose to send the deleted animal back and use status code 200 instead.

The in-memory API is temporary

The animals array and the nextId variable let us practice without a database. The data only exists in the running Node.js process, so restarting the server resets the data.
